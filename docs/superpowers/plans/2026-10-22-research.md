# W-D Research (River) — Implementation Plan

**Goal:** Replace the synthetic research engine with a real, user-triggered
River LLM analysis persisted per organization, with honest failure states.

**Architecture:** Migration `25_research.sql` (runs + findings), two read
policies, four RPCs (three authenticated reads/start + one service-role-only
completion), one Edge Function `research-analyze` (OpenAI-compatible River),
and a Flutter gateway + history UI. Provider secrets live only in Supabase
Edge Function secrets; the app never sees the key.

**Spec:** `docs/superpowers/specs/2026-10-22-five-features-design.md` §5.
**Provider:** River Inference — `POST https://api.river.ai/v1/chat/completions`
(OpenAI-compatible). Model default `deepseek-ai/DeepSeek-V4.1-Flash-1017`.

## Global Constraints

Same as W-A..W-C: RPC-only writes, RLS default-deny + narrow select, no
parameter defaults, redacted `write_audit`, paired `.down.sql`, no live apply,
no push. Org roles: `client | attorney | partner | compliance_officer`.
Research authority: active **attorney or partner**. The Edge Function never
trusts client-supplied context beyond ids; it reads the rows under the
caller's JWT so RLS decides what the model may see.

### HTTP contract (client and function must match exactly)

`POST /functions/v1/research-analyze` with the user's bearer token:

```json
{ "organization_id": "uuid", "matter_id": "uuid|null",
  "document_ids": ["uuid"], "question": "string (2..500 chars)" }
```

Success `200`:

```json
{ "run_id": "uuid", "status": "completed", "model": "string",
  "findings": [ { "headline": "string", "summary": "string",
                  "excerpt": "string|null", "source_type": "document|matter|none",
                  "source_id": "uuid|null" } ] }
```

Failure: non-2xx with `{ "error": "<code>" }` where code is one of
`unauthorized`, `forbidden`, `invalid_request`, `context_too_large`,
`provider_not_configured`, `provider_unavailable`, `invalid_response`.
A failed run is still persisted with `status='failed'` and the error code.

### Task 1: Migration + down

`supabase/migrations/25_research.sql`:

```sql
begin;

create table public.research_runs (
  id              uuid primary key default gen_random_uuid(),
  organization_id uuid not null references public.organizations (id) on delete cascade,
  matter_id       uuid references public.matters (id) on delete set null,
  requested_by    uuid references auth.users (id) on delete set null,
  status          text not null default 'running'
                    check (status in ('running','completed','failed')),
  model           text,
  prompt_summary  text not null check (length(trim(prompt_summary)) between 2 and 500),
  error_code      text,
  created_at      timestamptz not null default now(),
  completed_at    timestamptz
);

create index research_runs_org_created
  on public.research_runs (organization_id, created_at desc);
create index research_runs_matter
  on public.research_runs (matter_id) where matter_id is not null;

create table public.research_findings (
  id              uuid primary key default gen_random_uuid(),
  run_id          uuid not null references public.research_runs (id) on delete cascade,
  organization_id uuid not null references public.organizations (id) on delete cascade,
  headline        text not null check (length(trim(headline)) between 2 and 200),
  summary         text not null check (length(trim(summary)) between 2 and 4000),
  excerpt         text check (excerpt is null or length(excerpt) <= 2000),
  source_type     text not null default 'none'
                    check (source_type in ('document','matter','none')),
  source_id       uuid,
  sort_order      integer not null default 0,
  created_at      timestamptz not null default now()
);

create index research_findings_run
  on public.research_findings (run_id, sort_order);

alter table public.research_runs enable row level security;
alter table public.research_findings enable row level security;
revoke all on public.research_runs from anon, authenticated;
revoke all on public.research_findings from anon, authenticated;
grant select on public.research_runs to authenticated;
grant select on public.research_findings to authenticated;

commit;
```

Down: drop functions, findings, runs.

### Task 3: RPCs

Files: `supabase/rpc/start_research_run.sql`, `complete_research_run.sql`,
`list_research_runs.sql`, `list_research_findings.sql`; append drops.

**Signatures (no defaults):**
- `start_research_run(uuid, uuid, text) returns uuid`
- `complete_research_run(uuid, text, text, text, jsonb) returns void`
- `list_research_runs(uuid) returns setof public.research_runs`
- `list_research_findings(uuid) returns setof public.research_findings`

**Gates:**
- start: `is_active_member(p_organization_id)` and the caller's role in that
  org is `attorney` or `partner`; when `p_matter_id` is supplied it must belong
  to the same org and be readable by the caller (assigned/creator/partner).
  Insert `requested_by = auth.uid()`, status `running`, audit
  `research:start` (redacted; never the question).
- complete: **service_role only** (`revoke ... from public, anon,
  authenticated; grant ... to service_role`). Run must be `running`; status in
  `completed|failed`; a failed run requires `p_error_code`; a completed run
  requires a JSON array with 1..12 findings, each with a non-empty headline and
  summary. Insert findings with `organization_id` copied from the run; update
  the run (`status`, `model`, `error_code`, `completed_at`); audit
  `research:complete`.
- list runs: active member of the org; newest first.
- list findings: caller must be an active member of the run's org; ordered by
  `sort_order`.

### Task 5: Edge Function `research-analyze`

Files: `supabase/functions/research-analyze/index.ts`,
`supabase/functions/research-analyze/deno.json` (if the repo's other functions
have one), and a name-only update to `supabase/functions/.env.example`
(`RIVER_API_KEY`, `RIVER_BASE_URL`, `RIVER_MODEL`).

Flow:
1. CORS + OPTIONS.
2. Build a Supabase client with the caller's `Authorization` header (anon key);
   `auth.getUser()` → 401 on failure.
3. Parse/validate the body; reject a question outside 2..500 chars.
4. `start_research_run` via the user client → `run_id`.
5. Read the matter + requested documents under the user client (RLS). Compose
   context, cap at 12,000 characters → 422 `context_too_large`.
6. If `RIVER_API_KEY` is missing → mark the run failed
   (`provider_not_configured`) via the service client, return 409.
7. POST to `${RIVER_BASE_URL}/chat/completions` with
   `{ model: RIVER_MODEL ?? default, messages, temperature: 0.2 }`, 30 s
   timeout. Non-2xx/network → mark failed `provider_unavailable`, return 502.
8. Parse the model's JSON (strip code fences; accept
   `{findings:[...]}`). Invalid/shape-less → mark failed `invalid_response`,
   return 500.
9. Call `complete_research_run` with the service-role client; return the
   findings.

Prompt: a strict JSON-only instruction; every finding must cite either a
provided document id, the matter id, or `none`; no invented facts; the output
is explicitly labelled AI-generated. Never log the key, the question, or the
document bodies.

### Task 6: Dart data layer

- `ResearchRequest` value object (organizationId, matterId?, documentIds,
  question) in `lib/features/research/domain/`.
- `AiGateway` extended with `analyze(ResearchRequest)`,
  `fetchRuns({int limit = 20})`, `fetchFindings(String runId)`.
- `SupabaseResearchGateway`: invokes `research-analyze` via
  `SupabaseClient.functions.invoke`, maps status codes → typed `AppError`s;
  lists runs/findings through `list_research_runs` /
  `list_research_findings` RPCs. Env-gated seam; keep the synthetic gateway for
  env-less builds only, clearly labelled.
- Add a `providerConfigured` notion: a `provider_not_configured` error maps to
  an explicit unavailable state (never a fake result).
